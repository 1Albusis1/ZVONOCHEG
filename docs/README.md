## Исходная точка Z01

В репозитории есть проектная документация. Исходников прототипа для переноса UI в текущей версии нет. Новая веб-оболочка опирается на экраны из технического дизайна.

## Локальный запуск

Требуется Node.js 24. Из корня проекта установите зависимости и проверьте сборку.

```powershell
npm ci
npm run build
```

Запустите API и веб в двух терминалах PowerShell из корня проекта.

```powershell
. ./infra/local/env.ps1
npm run dev:api
```

```powershell
. ./infra/local/env.ps1
npm run dev:web
```

Откройте http://127.0.0.1:5173 и нажмите «Проверить подключение к API». API слушает http://127.0.0.1:3300/api/health. При конфликте портов измените их в `infra/local/env.ps1` и перезапустите оба процесса. Локальный запуск использует loopback и обходится без БД, внешних сервисов и данных участников.

## Прототип Z02.1

Запустите `npm run check:opaque -w @zvonocheg/crypto`. Тест в Node.js 24 проверяет вход через [@serenity-kit/opaque](https://github.com/serenity-kit/opaque) 1.1.0. Свежий вход открывает тестовый ключ аккаунта через HKDF-SHA-256 и AES-256-GCM. Тест проверяет отказ при неверном пароле и при подмене шифротекста. Используются случайный тестовый пароль и состояние в памяти. Браузер, Windows-клиент и восстановление истории проверяются в следующих пунктах Z02.

## Прототип Z02.2

Команда `node --test packages/crypto/mls.test.js` проверяет доставку сообщения в MLS-группе и отклонение ключа устройства, который отличается от ранее проверенного. Кандидат для прототипа — [ts-mls](https://github.com/LukaJCB/ts-mls) 1.6.4. В тесте исходный ключ передаётся по доверенному каналу. В приложении ещё предстоит выбрать способ его первичной проверки и показать предупреждение в интерфейсе. Выбор библиотеки для выпуска открыт.

## Прототип Z02.3

`node --test packages/crypto/*.test.js` проверяет восстановление двух непрочитанных MLS-сообщений в одной эпохе. Прототип сохраняет зашифрованную копию состояния получателя до отправки. После нового входа OPAQUE тест восстанавливает это состояние и читает сообщения по порядку.

Состояние содержит закрытый ключ подписи и секреты MLS. Для выпуска требуется проверить восстановление при смене эпох и отзыве устройства, а также предотвратить использование одной копии состояния для отправки с нескольких устройств. Архив прочитанных сообщений и проверка браузера и Electron описаны ниже.

## Проверка восстановления Z02.4

Из корня проекта выполните `npm ci` и `npm run check -w @zvonocheg/crypto`.
Запустите `npx vite --host 127.0.0.1 --port 5178 --strictPort` из корня.
Откройте `http://127.0.0.1:5178/packages/crypto/probe/` в чистом профиле Chromium. Страница должна показать «Восстановление истории прошло». Для прогона в Windows/Electron из второго терминала выполните:

```powershell
node node_modules/electron/cli.js packages/crypto/probe/electron.cjs http://127.0.0.1:5178/packages/crypto/probe/
```

Оба прогона используют тестовую страницу. Она проверяет свежий OPAQUE-вход, чтение сохранённого сообщения из архива и обработку MLS-сообщения, доставленного офлайн в той же эпохе.

## Результаты Z02.5

- Смена пароля переоборачивает ключ архива под новый OPAQUE export key. Старый пароль отклоняется, а старый export key не открывает новую копию.
- Модель записи архива сверяет версию и активность сессии. Тест отклоняет запись со старой версией и запись из отозванной сессии. Для API потребуется атомарная проверка версии при записи в БД.
- После удаления устройства его восстановленное MLS-состояние не читает сообщение новой эпохи. Уже доступные копии сохраняются.
- Тестовый серверный снимок содержит запись регистрации, серверную конфигурацию OPAQUE и зашифрованный архив. При полном компромиссе сервера стойкость к офлайн-подбору зависит от пароля и параметров растяжения ключа. Тест проверяет состав снимка и отказ при расшифровке посторонним ключом.

Для следующих прототипов оставляем `@serenity-kit/opaque` 1.1.0 и `ts-mls` 1.6.4. Перед выпуском предстоит проверить параметры OPAQUE, выбрать способ первичной проверки ключей устройств и определить модель архива, которая не клонирует активное MLS-состояние на несколько устройств. Восстановление через несколько смен эпох и интеграция с настоящим API и БД остаются открытыми.
