# Проверка LiveKit Z03

Для двух внешних сетей нужен тестовый LiveKit с публичным IP и WSS. Пример конфигурации находится в infra/local/livekit/livekit.example.yaml. Он включает ICE/UDP на 7882, ICE/TCP на 7881 и TURN/UDP на 3478. Добавьте серверные credentials через секреты окружения. Для проверки TURN/TLS настройте отдельный домен и сертификат по инструкции LiveKit.

1. Из корня выполните `npm ci` и `npm run dev:web`. На каждом компьютере откройте `http://127.0.0.1:5173/media-probe/` в Chromium.
2. Выпустите два короткоживущих токена с разными identity для одной тестовой комнаты. Введите адрес WSS и одинаковый случайный ключ, переданный участникам отдельно от токенов. Ключ передаётся клиентскому E2EE worker.
3. Подключитесь из двух внешних сетей и проверьте голос в обе стороны. В WebRTC Internals запишите тип и протокол выбранной ICE-пары. Повторите с галочкой «Только TURN» и подтвердите кандидата relay.
4. Повторите с разными ключами и проверьте отсутствие разборчивого аудио и закрытие соединения при ошибке E2EE.
5. Удалите участника. Для теста ротации перевыпустите токены для оставшихся участников в новой комнате и передайте им новый ключ. Проверьте, что старый ключ не расшифровывает новые дорожки. Этот сценарий моделирует смену ключа вручную. Автоматическая ротация внутри комнаты требует интеграции с управлением членством.

Для отдельной сборки стенда выполните `npm exec -w @zvonocheg/web -- vite build --config vite.media-probe.config.js --emptyOutDir`.

Сборка стенда и E2EE worker прошла. Результаты подключения из внешних сетей, принудительного TURN, несовпадения и ротации ключей ожидают прогона с тестовым сервером.
